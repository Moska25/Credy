Model card

What this model is, what it was fitted on, how well it works with intervals attached, and the specific circumstances under which it should not be used.

This card describes a model fitted to synthetic data. It is written in the form a real model card would take so that the form is demonstrated, but every number below comes from the generated population in app/generate.py. It is not a regulatory artefact and it has not been reviewed by anyone.

Intended use

What it is for. Demonstrating a credit risk evaluation and monitoring workflow end to end: temporal validation, interval estimation, calibration, drift detection and threshold economics. It is a teaching and engineering artefact.

What it is not for. Any real credit decision about any real person. The model has never seen a real applicant, its features are invented, and its economics are illustrative. It must not be used to score, rank, price or decline anyone.

Out-of-scope populations. Everything outside the generated distribution: other products, other geographies, other time periods, commercial lending, and any applicant population whose feature distribution differs from app/generate.py — which, given the drift results on this very site, means populations only a few months away.

Data and the generating process

Applications are drawn from an explicit logistic data-generating process. The full specification, the data dictionary and the drift schedule are on the data page. In summary:

logit P(default) = b0(month) + sum_j beta_j * feature_j + beta_missing * 1[field absent]

Four drifts are injected on a documented schedule and each can be switched off independently in app/generate.py: a covariate shift in income level and channel mix from month {{ truth.schedule.covariate_shift.starts_month }}, a prior-probability shift from month {{ truth.schedule.prior_shift.starts_month }}, a concept drift in the broker channel coefficient from month {{ truth.schedule.concept_drift.starts_month }} (from {{ truth.schedule.concept_drift.coef_month_1 }} to {{ truth.schedule.concept_drift.coef_month_24 }}), and a data-quality drift in employment_tenure missingness from month {{ truth.schedule.quality_drift.starts_month }}.

Why some estimates are attenuated. z_log_income, log_loan_amount and loan_to_income are algebraically related — loan-to-income is loan divided by income — so the true income effect is split across three collinear columns and none of them recovers it alone. This is a real property of the fit, not a bug, and it is the reason coefficient magnitudes from a correlated design should never be read as feature importances. Signs and the broadly correct ordering of the uncorrelated features are what the comparison can honestly support.

Limitations

  • data
    Synthetic. Every relationship in it was written by hand, so the model is being tested on a world it can in principle fit perfectly. Real applicant data contains structure no generator thought of.
  • labels
    Default is observed for every application, including declined ones. Real portfolios only observe outcomes for approved applicants, which biases every refit. No reject inference is implemented.
  • horizon
    Default is a single binary flag with no time-to-event. There is no notion of when a loan went bad, so no survival or lifetime-PD view is possible.
  • economics
    One period, no funding cost, no operational cost, no recovery curve, no prepayment. Loss given default is a constant rather than a distribution.
  • selection
    The champion was chosen by comparing three models on the validation window, and this card then reports test numbers for all three. Reporting a selected model's test performance without accounting for the selection is mildly optimistic.
  • intervals
    Bootstrap intervals assume applications are independent draws. They quantify sampling noise only — not model risk, not specification error, and explicitly not the risk that next month's population differs from this month's.
  • explanations
    No SHAP or per-application reason codes. A production credit model needs adverse action reasons; this one cannot produce them.

Ethical notes

Automated credit decisions harm people when they are wrong. A false decline is not a rounding error to the person declined; it is a refused loan. The false decline cost in the policy simulator is a crude stand-in for that, and treating it purely as lost margin understates it.

Subgroup results here are a diagnostic, not a fairness audit. See the subgroups page for what that distinction means. Widest observed spread on this dataset: {% if sg.widest_gap %}{{ sg.widest_gap.dimension }}, {{ sg.widest_gap.worst_auc | fnum }} to {{ sg.widest_gap.best_auc | fnum }} AUC, with {{ "overlapping" if sg.widest_gap.overlapping_intervals else "disjoint" }} intervals. {% else %}not computable at these cohort sizes.{% endif %}

Features that proxy for protected characteristics are not screened. Age is used directly as a feature here. In several jurisdictions that alone would make the model unlawful for consumer credit. It is present because this is a laboratory for stability measurement, and its presence should be read as a demonstration of what a model card has to disclose — not as a defensible design choice.

Drift is a safety issue, not just an accuracy issue. The alerts on this site fire months after the drift begins. A model that is quietly under-predicting risk is also quietly approving people who cannot afford the loan.
